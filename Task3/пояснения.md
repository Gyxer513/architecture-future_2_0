#  1. Структура тех-радара

Каждая точка — «технология / подход / платформа» — живёт в координатах: **квадрант + кольцо**.

## Квадранты

| Квадрант                 | Смысл                                                 | Примеры из твоего RAIDAR                                                               |
|--------------------------|-------------------------------------------------------|----------------------------------------------------------------------------------------|
| **Techniques**           | Методологии, архитектурные паттерны, практики         | Data Mesh, Event‑driven architecture, Data Contracts, Privacy by Design, IaC + GitOps   |
| **Tools**                | Конкретные инструменты разработки, аналитики и оркестрации | Airflow, dbt Core, Great Expectations, Prometheus + Grafana                           |
| **Platforms**            | Инфраструктура, хранилища и шины данных               | Apache Kafka, Iceberg / Delta Lake, Object Storage, Terraform                          |
| **Languages & Frameworks** | Языки и каркасы для сервисов и UI                     | Python, Java/Kotlin, TypeScript / React, .NET 8                                        |

## Кольца зрелости

> Кольца отражают **зрелость**, а **не приоритет**.

- **ADOPT** – стандартизированные элементы, база производственной эксплуатации.
- **TRIAL** – мы внедряем в пилотах, формируем экспертизу.
- **ASSESS** – наблюдаем и тестируем рынок.
- **HOLD** – планируем выводить.

#  2. Связь технологий с бизнес‑сценариями

Радар визуализирует, какие технологии решают какие бизнес‑кейсы.

| Технологический домен                     | Бизнес‑сценарии, которые поддерживает                                 | Эффект                                                                 |
|-------------------------------------------|------------------------------------------------------------------------|------------------------------------------------------------------------|
| **Data Mesh / Data Contracts**            | Автономное владение доменными зонами: «финансы», «медицина», «ИИ» и т.д. | Масштабирование, независимость подразделений, разгрузка централизованной data team |
| **Event‑driven architecture + Kafka/Pulsar** | Реал‑тайм оповещения: антифрод, статусы анализов, финоперации          | Сокращение задержек, мгновенные реакции                               |
| **Lakehouse (Iceberg/Delta)**             | Единое хранилище медицинских и финданных с откатами по времени         | Гибкая отчётность, снижение стоимости хранения                        |
| **Airflow / Prefect / Argo**              | Оркестрация любых data pipeline, зависимости и расписания             | Гарантированная доставка данных, надёжная ML-инфраструктура           |
| **dbt + Semantic Layer**                  | Быстрое построение новых витрин BI                                     | Единые метрики, self‑service аналитика                                |
| **Data Quality as Code / Great Expectations** | Проверка SLA перед публикацией в BI                                    | Отчёты без ошибок, уменьшение ручных сверок                           |
| **Privacy by Design / ABAC / IAM**        | Защита PHI / финданных по ролям и атрибутам                            | Соответствие регуляторике, репутационные риски = 0                    |
| **MLflow + Feature Store + MLOps**        | Регистрация, развёртывание и повторное использование моделей ИИ        | Сокращение времени внедрения моделей с месяцев до дней                |
| **FinOps / Cost Governance**              | Контроль и оптимизация облачных расходов по Data Mesh                  | Опережающее управление TCO                                            |
| **TypeScript/React + Portal**             | Самообслуживание аналитиков и руководителей                            | Повышение скорости принятия решений ×4                               |

#  4. Для чего это нужно

| Направление                         | Эффект / зачем                                                                 |
|-------------------------------------|---------------------------------------------------------------------------------|
| **От DWH → Lakehouse / Mesh**       | Теперь данные обновляются онлайн (минуты → секунды): отчёты врача или финдиректора на основе актуального стейта пациентов и транзакций. |
| **Data Governance / Quality**       | Исключает рутину бэк‑офиса (офис‑анализ — в автомате). Минимизирует ошибки, не идёт в регуляторный risk. |
| **Self‑Service Portal**             | Каждый отдел строит дашборды сам — без dev‑нагрузки, высвобождение ×20 чел.д на Sprint. |
| **MLOps / AI**                      | Автоматическое встраивание предиктивных моделей = лучшее решение в BI/Medicine за секунды. |
| **FinOps / IaC**                    | Каждая новая команда разворачивает энв двумя командами CLI. Прозрачная стоимость ресурсов, OPEX с электронным контролем. |
